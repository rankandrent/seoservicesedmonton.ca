# Learnings: seo-keyword-researcher

## Owner rules (highest priority — written by the site owner, never removed by agents)

- (owner) Pick only keywords with verified search volume above 0: Ahrefs API country `ca`, else Google Search Console impressions for the exact query (figure + date range), else Semrush database `ca`. Record `volume`, `kd`, `dataSource` and the date in the brief; never estimate. No number from any source → return "BLOCKED: no volume data" so the orchestrator stops and tells the owner. Every brief lists `entities` (15–25) and `attributes` (8–12); the on-page script scores coverage against them.
- (owner, concept bindings) Every brief for a new page adds `bindings` {synonyms, plural, parent, children, related}, `essential` (2–3 concepts: entity + key attribute + qualifier such as the town or industry), `queryVariants` (3–5), `ambiguous` (word → context word) and `siteFacts` copied from the money page. Good: "Google Business Profile optimization" → synonyms ["GBP optimization", "Business Profile management"], parent ["local SEO"], children ["categories", "services list", "photos", "review responses"]. Bad: a flat entity list with no relation types.
- (owner, final) Titles: the planned meta title starts with the exact primary keyword, then " | " and a short benefit; no ":" in any title or H1. The H1 carries the exact keyword joined with plain words or a comma.
- (owner) Google's AI Overview and People Also Ask for the primary keyword are required inputs. The brief's `aiOverview` (cited sources, entities, attributes, terms, questions) and `paa` must each be covered on the page with a real fact, and every PAA question answered in an H2/H3 or FAQ; one missing item fails QA.
- (owner, final) Protect live rankings: never change a live page's slug; never change a live page's meta title or og:title without the owner's explicit approval for that page. Pre-launch (indexable: false) titles may still be fixed.
- (escalated rule from the source site) Every keyword that is not a plain noun phrase needs a carrier pattern in the brief (`keywordCarrier`): question forms, "X vs Y" pairs and keywords with the place name last ("hvac seo edmonton"). A carrier must be a full grammatical phrase on its own. Good: "the local SEO vs Google Ads question", "an Edmonton plumbing SEO campaign". Bad: "weighing local SEO vs Google Ads" (article on one half only), "a plumbing seo edmonton project" (keyword stacked as a modifier).
- (escalated rule from the source site) Write every `entities` and `attributes` entry as words the page will literally print, because the on-page script matches them literally. Entities: one name per entry, optional short form in brackets only at the END ("Google Business Profile (GBP)"); no lists, slashes or brackets in the middle. Attributes: the label is the noun the writer will use, the value goes inside brackets ("review response time (within 2 business days)"). Before handoff, print each entry and read it as a phrase you expect to see on the page.

## Lessons (learned from runs, QA, audits and results)

- Cannibalisation is not only titles and keywords: check every existing page's H2s and FAQ questions too. If a money page already has an H2 that answers the query (for example a cost H2), reject the query as a post keyword and pick a buyer-evaluation angle that links up to that section.
- Test the keyword tool with one call before planning around it. When WebFetch is blocked, get each competitor page's coverage from `<domain> <title>` WebSearch snippets, set unknown volume/KD to null and say so in `dataSource`. Never estimate.
- Unsourced numbers on competitor pages ("3x more calls") go into the brief `notes` as "do not use", so the writer does not pick them up.
- Do not default every new cluster's commercial post to "how to choose an agency". Look for a buyer-action query the money page does not own, and park the agency-choice topic as a deferred candidate.
- Set the funnel stage from the SERP's dominant page type, not from how close the topic is to the service. How-to guides dominating page 1 = MOFU; BOFU only when cost, pricing, agency or vendor-comparison pages dominate.
- WebSearch every candidate's page 1 before choosing, even with good volume: a high-volume phrase can mean training courses, a different country's law or a directory intent. Drop secondary keywords whose page 1 has a different intent and write why in `secondaryNote`.
- When the money page already owns cost, process and deliverables, test these angles in order: "<service> vs <alternative>", "<service> ROI / payback", "<service> RFP / scope of work", per-unit cost ("cost per <unit>"), "is <phase> worth it". Pick the wording whose SERP is vendor-dominated.
- Before choosing a "<thing> cost" BOFU keyword, check that the site publishes a price for that exact thing. If it does not (prices are an open owner question here), do not brief a cost post that would need invented numbers.
- Grep the central entity across ALL content files (services, industries, core pages, blog) for numeric thresholds, price labels, team sizes and naming. Tell the writer which page's wording to follow and list every conflict in `notes`.
- Grep case studies for the entity before outlining. No real match → write "no DOWN link, no client results" in `notes`, label any worked example as illustrative, and do not plan a mini-case intro. (Here all case studies are drafts until the owner supplies real data.)
- When a money page has a section that owns a fact (price, process), put a deep link to that section in `internalTargets` so the writer links instead of restating it.
- State density targets as word share and as a count: max uses = 0.02 × expected words ÷ words in the keyword (about 13–15 for a 3-word keyword in 2,000–2,300 words). For question-form keywords (5+ words), cap at about 8 and prescribe object-position carriers ("knowing how to get more Google reviews…").
- A prescribed description must be complete: keyword first, what the reader gets, then a next step that matches the funnel, within the length limit, with no apostrophe near the limit (entities add characters in built HTML). Read every pronoun in it back to its noun.
- Treat the brief's own example sentences, leadAngle wording and suggested team or process wording as unverified: run the implied-client test ("X teams work with us", "we are often asked") and a money-page wording diff on every sentence the brief prescribes, because writers paste "use as written" text verbatim.
- Give every `backlinkSuggestions` entry a `priority` of `required` or `skip` (with a reason); use `conditional` only with a named blocker you cannot check yourself. Never write "optional" — the pipeline drops optional items.
- Before marking a suggestion `conditional` because a field "may render as plain text", check the component in one grep (`components/sections.tsx`): most text fields here render inline marks through `rich()`.
- Keep generic, high-frequency nouns out of `entities` (they outnumber the keyword and break the salience check). Use their specific forms ("Google Maps calls", not "calls"), and name in `density` the 2–3 entities that must stay under the keyword count.
- Entities whose short form sits inside common words (for example "GEO" in "geography", "NAP" in "snap") inflate the on-page count: leave the short form out or use the full name. Drop any short form that is a substring of the keyword.
- When a keyword holds a punctuated or 2-letter token, state the exact literal form in `keywordCarrier.spellingNote`; the meta checks tolerate word order, but the salience count needs the literal phrase.
- When the SERP API returns an empty result for a low-volume term, run one control keyword to prove the call works, then record `aiOverview.present: null, status: "unverified"` (never "false") and fill the fields from the WebFetched top organic pages (`proxySources`) and their FAQ questions.
- For every deep link in a link plan, read the target H2 and its first paragraph and write an anchor that names what that section actually covers; reject a target whose heading only shares a word with the anchor.
- When an angle depends on a team capability (a language, on-site visits, regulated-industry handling), grep the site for it first. If no page states it, turn it into a user or product requirement and add an owner question; never let it into the brief as a claim.
- For a location-flavoured brief, grep the case studies and content for real clients in that town. A real local client is kept off the page by default and raised as an owner question, never treated as permission to claim local clients.
- In a brief modelled on a sibling page, prescribe only FACT strings (prices, durations, process names). For every other sentence give the content plus "write in new words", never a full sentence copied from the sibling page (copied sentences pushed 5-gram overlap above the 12% limit).
- Build the variety check from `ledger.json → posts` in date order and look up each fingerprint wherever it sits; name the nearest structural relative anywhere on the site in `variety.differsFrom` and list what the new page must NOT reuse from it.
- Before planning a quote or testimonial intro, read the quote and its speaker. Use it only if the speaker is the client and it praises work this site sells; otherwise write "do not present as a testimonial about us". (Here: no testimonials exist until the owner supplies them.)
- When an AI Overview names a regulation, state only the link between rule and page topic that a primary or legal source confirms, and record any regulation left out (and why) in the brief.
