# Site audit, 2026-10-23 (pre-launch)

Scope: every HTML page in `out/` (37 files: 33 indexable-type pages, 3 case-study drafts, `thank-you`, `404`; the brief said 39, but the current build only has 37). Each page is checked against the owner rules in `photography-forum/.claude/skills/seo-patent-rules/SKILL.md` and `photography-forum/docs/content-system/RULES.md` (keyword and meta, US8126832B2 concept bindings, US12393768B2 layout, US6285999 and US9558233B1 links, honesty), plus `plan/content-plan.json`.

Method: I parsed the built HTML (title, meta, og, H1/H2, visible `<main>` text, links by type and position, tables, JSON-LD) and compared it with each page's plan entry. Entity and attribute coverage started with literal or variant matching on visible text, with `[[placeholders]]` removed because a placeholder is not a fact. I then reviewed every miss by hand and counted clear semantic matches (for example "Photos and posts" = "GBP posts and photos"). "Exact keyword" means the plan's primary keyword word for word, ignoring case and hyphens. SERP data comes from Ahrefs `serp-overview` (CA), 5 calls, one per priority keyword.

Global facts that apply to every row:

- **No `<meta name="keywords">` is emitted on any page.** "First meta keyword" fails everywhere. See finding 1.
- og:title, og:description and twitter tags copy the title and description, so every og result equals the title/description result.
- Every page is `noindex, nofollow` (`SITE.indexable: false`), which is correct pre-launch.
